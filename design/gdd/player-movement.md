# 플레이어 이동 시스템 (Player Movement System)

> **Status**: Draft — Updated post-prototype
> **Author**: 김재현 + agents
> **Last Updated**: 2026-04-21 (prototype v4 반영 — 스와이프→조이스틱, 경로 제한 이동)
> **Implements Pillar**: 읽으면 이긴다, 공정한 죽음

## Overview

플레이어 이동 시스템(Player Movement System)은 터치 입력을 8×8 그리드 위의 이동으로
변환하는 Core Layer 시스템이다. 플레이어는 항상 그리드 위의 단 하나의 셀을 점유하며,
터치 입력이 감지되면 즉시 인접 셀로 이동한다. 이동 방향(4방향 vs 8방향)은 Detailed Design
에서 확정된다.

기술 구조 측면에서, 이 시스템은 터치 입력 시스템으로부터 조이스틱 방향 신호를 수신하고,
그리드 폭발 시스템으로부터 현재 셀 상태를 조회하여 이동 유효성을 판단한다. 플레이어는
사전에 정의된 경로(PATH) 위의 셀로만 이동할 수 있다. 처리 순서는 이동 처리 → 폭발 판정
— 이동이 먼저 처리되어야 게이트 폭발 전 탈출이 가능하다(grid-explosion A-4). 이동이
완료된 셀에서 폭발 판정이 발생하면 그리드 폭발 시스템이 사망을 처리한다.

플레이어 체험 측면에서, 이 시스템은 "읽으면 이긴다"의 실행 수단이다. 패턴을 읽어서 안전 칸을
파악해도, 거기까지 이동할 수 없다면 지식은 쓸모없다. 이동 시스템은 "아는 것"을 "행동"으로
변환하는 유일한 경로이며, 터치 응답성과 이동 즉시성이 "공정한 죽음" 필러와 직결된다.
"알았는데 손이 느렸다"는 경험은 이 시스템이 구조적으로 차단해야 한다.

## Player Fantasy

### 핵심 감정

이동 시스템은 "읽으면 이긴다"의 실행 경로다. 플레이어가 느끼는 것은 단순한 이동이 아니다 —
**인지가 즉시 몸이 되는 일체감**이다. 붉은 예고가 그리드를 물들이는 순간, 시선이 안전한
한 칸을 찾아낸다. 탭. 그 칸에 서있다. 방금 서있던 칸이 사라진다. 읽은 것이 그대로
손끝에서 실현되었다 — 생각과 결과 사이에 지연이 없었다.

이 판타지는 하나의 약속 위에 선다: **손이 느려서 죽는 일은 없다**. 이동 시스템의
즉시성은 "공정한 죽음" 필러의 기술적 토대다. 죽음이 있다면 그것은 읽지 못한 결과이지,
조작이 늦은 결과가 아니다. 플레이어는 이 약속을 의식적으로 알지 못해도, 그것을 신뢰하며
더 과감하게 마지막 순간까지 기다렸다 탈출하는 플레이를 시도하게 된다.

### 판타지 문장

> 플레이어는 **생각과 행동이 하나인 사람**이 된다. 보는 순간 이미 거기 있다.
> 폭발이 내 발밑을 삼킬 때 나는 이미 다음 칸에 서 있다.

### MDA 연결

- **Challenge** (primary): 정확한 칸을 골라 정확한 순간에 이동하는 인지-실행 일체 도전
- **Sensation** (secondary): 즉시 이동의 물리적 쾌감, 폭발 직전 탈출의 아드레날린

## Detailed Design

### Core Rules

**PM-1. 이동 방향 (8방향)**
상(↑) / 하(↓) / 좌(←) / 우(→) / 좌상(↖) / 우상(↗) / 좌하(↙) / 우하(↘)
대각선 이동 시 행과 열이 동시에 1씩 변경된다.

**PM-2. 이동 처리 방식**
1. 입력 감지 → **논리 좌표(CellCoord) 즉시 변경** → 비주얼 트윈 0.1s 시작
2. 폭발 판정은 논리 좌표 기준으로 수행된다 (비주얼 위치 무관)
3. 처리 순서: 이동 처리 → 폭발 판정 (grid-explosion A-4 준수)
4. 트윈 중에도 논리 점유는 목적지 셀로 확정 상태다

**PM-3. 터치 입력 (플로팅 조이스틱)**
1. 화면 어느 위치에서든 터치 시작 → 터치 지점을 조이스틱 원점으로 설정
2. 드래그 변위가 `JOY_THRESHOLD`(기본 18px) 초과하면 방향 활성화
3. 변위 각도를 8방향 구간(45도 단위)으로 매핑 — 가장 가까운 방향 선택
4. 방향 활성화 즉시 첫 이동 실행, 이후 `MOVE_REPEAT`(0.22s) 간격으로 연속 이동
5. 방향이 바뀌면 즉시 새 방향으로 첫 이동 실행 (타이머 리셋)
6. 터치 해제 → 연속 이동 정지
7. 사망 상태에서 터치 → 재시작 (이동 아님)

**PM-4. 입력 버퍼링**
1. 트윈 진행 중(0.1s) 새 입력이 들어오면 버퍼 1개에 저장
2. 버퍼는 최신 입력으로 덮어쓴다 (큐 누적 방지)
3. 트윈 완료 즉시 버퍼에 입력이 있으면 연속 실행

**PM-5. 이동 제약 규칙**

| 조건 | 처리 |
|------|------|
| 그리드 경계 밖 이동 | 이동 불가, 입력 무시 (버퍼 소모 없음) |
| **경로(PATH) 외 셀로 이동** | **이동 불가, 입력 무시 — 경로 셀로만 이동 가능** |
| 사망 상태에서 입력 | 이동 불가, 입력 무시 |
| Exploded 게이트 셀로 이동 | 허용 → 논리 점유 이동 → 착지 즉사 (사전 차단 없음) |

**PM-6. 다중 플레이어 점유**
같은 셀에 여러 플레이어가 동시에 점유할 수 있다. 충돌 처리 없음.
시각 표현은 같은 셀 내 플레이어를 약간의 오프셋으로 구분한다 (렌더링 책임).

### States and Transitions

플레이어는 2개의 상태를 가진다. Moving은 Alive의 서브스테이트다.

| 상태 | 진입 조건 | 종료 조건 | 이동 가능 여부 |
|------|----------|----------|-------------|
| **Alive** | 라운드 시작 | 폭발 판정 사망 | 가능 |
| **Alive / Moving** | 유효한 이동 입력 수신 | 트윈 완료 (0.1s) | 버퍼 1개 허용 |
| **Dead** | 폭발 판정 PLAYER_KILLED | 라운드 종료 / 부활 (라운드 매니저) | 불가 |

### Interactions with Other Systems

| 방향 | 대상 시스템 | 데이터 | 소유권 |
|------|-----------|--------|-------|
| **입력 수신** | 터치 입력 시스템 (미설계) | `{ direction: Direction8 }` | 터치 입력 시스템 *(provisional)* |
| **상태 조회** | 그리드 폭발 시스템 | `getCellState(coord): CellState` | 그리드 폭발 시스템 |
| **이동 이벤트 발행** | 그리드 폭발 시스템 | `PLAYER_MOVED { playerId, from: CellCoord, to: CellCoord, timestamp }` | 플레이어 이동 시스템 |
| **착지 이벤트 발행** | 라운드 매니저 | `PLAYER_ARRIVED { playerId, cell: CellCoord, timestamp }` — 트윈 완료(t=0.1s) 시점에 발행. Goal Cell 감지에 사용. | 플레이어 이동 시스템 |
| **사망 수신** | 그리드 폭발 시스템 | `PLAYER_KILLED { playerIds: PlayerId[], cellId: CellCoord, timestamp }` | 그리드 폭발 시스템 |
| **위치 공급** | 라운드 매니저 | 현재 플레이어 위치 조회 인터페이스 *(provisional)* | 플레이어 이동 시스템 |

## Formulas

**F-1. 스와이프 방향 매핑 (Swipe → Direction8)**

```
direction = round(swipe_angle / 45) mod 8
```

- `joy_angle`: 조이스틱 변위 벡터의 각도 (0° = 우, 시계 방향 증가, 범위 0–360°)
- 결과: 0=우(→) / 1=우하(↘) / 2=하(↓) / 3=좌하(↙) / 4=좌(←) / 5=좌상(↖) / 6=상(↑) / 7=우상(↗)
- 변위 거리 < `JOY_THRESHOLD`(18px) → 매핑 불수행, 입력 무시
- 출력 범위: Direction8 ∈ {0, 1, 2, 3, 4, 5, 6, 7}

**F-2. 이동 목적지 계산 (Target Cell)**

```
target_row = current_row + Δrow[direction]
target_col = current_col + Δcol[direction]
```

델타 테이블:

| Direction | 이름 | Δrow | Δcol |
|-----------|------|------|------|
| 0 | 우(→) | 0 | +1 |
| 1 | 우하(↘) | +1 | +1 |
| 2 | 하(↓) | +1 | 0 |
| 3 | 좌하(↙) | +1 | -1 |
| 4 | 좌(←) | 0 | -1 |
| 5 | 좌상(↖) | -1 | -1 |
| 6 | 상(↑) | -1 | 0 |
| 7 | 우상(↗) | -1 | +1 |

출력 범위: row ∈ [0, 7], col ∈ [0, 7]

**F-3. 경계 유효성 검사 (Boundary Check)**

```
is_valid = (0 ≤ target_row ≤ 7) AND (0 ≤ target_col ≤ 7)
```

- is_valid = false → 이동 불가, 입력 무시
- 출력: boolean

**F-4. 트윈 보간 (Visual Position Interpolation)**

```
visual_pos(t) = lerp(start_pos, target_pos, t / MOVE_TWEEN_DURATION)
lerp(a, b, α) = a + α × (b - a)
```

- `t`: 트윈 경과 시간 (0 ~ MOVE_TWEEN_DURATION)
- `MOVE_TWEEN_DURATION` = 0.1s (기본값, Tuning Knob)
- 논리 좌표는 t=0 시점에 이미 target으로 확정됨 (F-4는 시각 전용)
- 출력: 화면 픽셀 좌표 (렌더링 시스템 전달)

## Edge Cases

**EC-1. 트윈 진행 중 폭발 판정 발생**
조건: 이동 트윈 비주얼이 0.1s 진행 중에 출발 셀이 Exploded로 전이됨
→ 논리 점유는 이미 목적지로 변경된 상태이므로 폭발 판정 대상이 아님
→ 출발 셀의 폭발은 해당 플레이어에게 영향을 주지 않는다
이유: 논리 점유가 입력 즉시 변경되며, 폭발 판정은 논리 좌표 기준 (PM-2 + grid-explosion A-4)

**EC-2. 경계 밖 이동 시도**
조건: 이동 방향이 그리드 경계 밖을 가리킴 (예: row=0에서 ↑ 입력)
→ F-3 경계 검사 실패 → 이동 불가, 입력 무시
→ 버퍼가 있다면 버퍼는 그대로 유지된다 (버퍼 소모 없음)
→ 플레이어 위치 변경 없음

**EC-3. 버퍼 입력이 현재 위치에서 경계 밖**
조건: 트윈 완료 후 버퍼 실행 시점에, 저장된 방향이 새 위치에서 경계 밖
→ F-3 재검사 → 이동 불가, 버퍼 소모 (무시되고 비워짐)
예: (0,6)에서 우(→) 버퍼 저장 후 트윈으로 (0,7) 도착 → 버퍼의 우(→) 재계산 → col=8 → 경계 밖 → 무시

**EC-4. 두 플레이어 교차 이동**
조건: Player A가 셀 X→Y로, Player B가 셀 Y→X로 동시에 이동
→ 두 플레이어 모두 목적지로 이동 완료
→ 중간 교차 자체는 판정 없음 — 논리 점유는 원자적으로 변경됨
→ 결과: A는 Y에, B는 X에 각각 위치

**EC-5. 우발적 마이크로 스와이프**
조건: 미세한 손 흔들림으로 JOY_THRESHOLD 미만 조이스틱 변위 발생
→ PM-3 규칙: 거리 < JOY_THRESHOLD → 입력 무시
→ 의도하지 않은 이동 방지

**EC-6. 사망 처리와 버퍼 입력이 같은 타임스텝에 겹침**
조건: PLAYER_KILLED 수신 타임스텝에 버퍼에 입력이 남아있음
→ 사망 처리가 먼저 적용됨 → 플레이어 상태 Dead로 전환
→ Dead 상태에서 버퍼 실행 불가 (PM-5) → 버퍼 파기
→ 사망 이후 입력이 처리되는 경우 없음

**EC-7. 라운드 종료 시 이동 트윈 진행 중**
조건: 라운드 종료 이벤트가 트윈 0.1s 도중에 도착
→ 트윈을 즉시 목적지로 스냅 (트윈 중단)
→ 라운드 결과는 논리 좌표 기준으로 처리 (비주얼 위치 무관)

## Tuning Knobs

| 변수 | 현재값 | 안전 범위 | 영향 게임플레이 |
|------|--------|---------|--------------|
| `MOVE_TWEEN_DURATION` | 0.1s | 0.0–0.15s | 이동 비주얼 속도. 확정값. |
| `JOY_THRESHOLD` | 18px | 10–30px | 조이스틱 방향 활성화 최소 변위. 낮추면 미세 움직임도 인식, 높이면 의도적 드래그만 인식. |
| `MOVE_REPEAT` | 0.22s | 0.12–0.40s | 조이스틱 누름 유지 시 연속 이동 간격. 낮추면 빠른 연속 이동, 높이면 느린 연속 이동. |

### 튜닝 가이드

- **이동이 무겁게 느껴짐**: MOVE_TWEEN_DURATION 감소 (0.08s까지)
- **연속 이동이 너무 빠름**: MOVE_REPEAT 증가 (0.28–0.35s)
- **조이스틱 오작동 잦음**: JOY_THRESHOLD 증가 (22–25px)

## Visual/Audio Requirements

### 비주얼 사양

**V-1. 플레이어 캐릭터 (로컬)**
- 형태: 셀 크기의 60% 정사각형, 모서리 챔퍼 3px
- 외곽선: #FFFFFF 2px solid
- 방향 인디케이터: #00E5CC 등변삼각형, 셀 크기의 35%, 현재 마지막 이동 방향을 가리킴
- 렌더링: Graphics 컴포넌트 draw call 1개 (외곽선 + 삼각형 포함)
- 배경 채우기: 없음 (투명 — "어둠은 안전이다" 비주얼 룰)

**V-2. 이동 트윈 비주얼**
- 보간 방식: 선형 lerp (ease/spring/오버슈트 없음 — 즉시성 강조)

- 방향 삼각형: 없음 (상대의 의도 노출 방지)
- 겹침 처리: 같은 셀에 2명 이상 → 각 4px 오프셋 (렌더링 시스템 담당)

**V-4. 도착 VFX (이동 완료 시)**

## Acceptance Criteria

#### BLOCKING — 자동화 테스트 필수

**AC-PM-1. 8방향 델타 정확성**
입력: direction 0–7 각각. 기대: target_row = current_row + Δrow[direction], target_col = current_col + Δcol[direction] (F-2 테이블 일치).

**AC-PM-2. 경계 밖 이동 — 위치 불변**
입력: 경계 셀에서 경계 밖 방향 스와이프. 기대: 플레이어 논리 좌표 변경 없음.

**AC-PM-3. 경계 밖 이동 — 버퍼 소모 없음**
입력: 경계 밖 이동 시도 중 버퍼에 유효 입력 존재. 기대: 버퍼 입력 보존됨.

**AC-PM-4. 논리 좌표 즉시 변경**
입력: 유효 이동 입력. 기대: 트윈 시작 시점(t=0)에 논리 좌표가 목적지로 확정됨.

**AC-PM-5. 트윈 중 입력 버퍼링**
입력: 트윈 진행 중(t < 0.1s) 유효 방향 입력. 기대: 버퍼에 1개 저장됨.

**AC-PM-6. 버퍼 덮어쓰기**
입력: 트윈 진행 중 방향 A 입력 후 방향 B 입력. 기대: 버퍼에 B만 남음 (A 소멸).

**AC-PM-7. 버퍼 자동 실행**
입력: 트윈 완료 시 버퍼에 유효 입력 존재. 기대: 즉시 해당 방향으로 이동 시작.

**AC-PM-8. Dead 상태 이동 불가**
입력: 사망 후 스와이프. 기대: 논리 좌표 변경 없음.

**AC-PM-9. Dead 상태 버퍼 파기**
입력: 버퍼 보유 중 PLAYER_KILLED 수신. 기대: 버퍼 비워지고 이동 발생 없음.

**AC-PM-10. JOY_THRESHOLD 미만 입력 무시**
입력: 드래그 변위 < JOY_THRESHOLD(18px). 기대: 방향 활성화 안 됨, 이동 없음.

**AC-PM-11. 출발 셀 폭발 — 논리 좌표 기준 판정**
입력: 이동 트윈 진행 중 출발 셀이 Exploded로 전이. 기대: 플레이어 사망 없음 (논리 점유는 목적지 셀).

**AC-PM-12. Imminent 셀로 이동 허용**
입력: Imminent 상태 셀 방향 스와이프. 기대: 이동 처리됨 (사전 차단 없음).

**AC-PM-13. Exploded 셀 착지 사망**
입력: Exploded 셀로 이동. 기대: 논리 점유 이동 완료 후 폭발 판정 → PLAYER_KILLED.

**AC-PM-14. EC-3 버퍼 재계산**
입력: (0,6)에서 우(→) 버퍼 저장 → 트윈으로 (0,7) 도착. 기대: 버퍼의 우(→) 재계산 → col=8 → 무시 → 버퍼 소모.

**AC-PM-15. EC-4 교차 이동 — 두 플레이어 모두 목적지 도달**
입력: Player A: X→Y, Player B: Y→X 동시 이동. 기대: A는 Y에, B는 X에 위치.

**AC-PM-16. EC-6 사망-버퍼 동일 타임스텝**
입력: 버퍼 보유 중 같은 타임스텝에 PLAYER_KILLED. 기대: 사망 처리 우선 → 버퍼 파기.

**AC-PM-17. EC-7 라운드 종료 — 트윈 즉시 스냅**
입력: 트윈 진행 중 라운드 종료 이벤트. 기대: 논리 좌표 기준 위치로 비주얼 즉시 스냅.

**AC-PM-18. PLAYER_MOVED 이벤트 발행**
입력: 유효 이동 완료. 기대: `PLAYER_MOVED { playerId, from: CellCoord, to: CellCoord, timestamp }` 발행됨.

**AC-PM-18b. PLAYER_ARRIVED 이벤트 발행**
입력: 이동 트윈 완료(t=0.1s 경과). 기대: `PLAYER_ARRIVED { playerId, cell: CellCoord, timestamp }` 발행됨. `cell`은 트윈 목적지와 일치해야 함.

**AC-PM-19. 다중 플레이어 동시 점유**
입력: 두 플레이어가 같은 셀로 이동. 기대: 두 플레이어 모두 해당 셀에 논리 점유, 충돌 없음.

**AC-PM-20. F-1 스와이프 각도 매핑 — 8방향 경계값**
입력: 각 방향 경계각 (22.5°, 67.5°, 112.5° 등). 기대: round(angle/45) mod 8 수식과 일치.
