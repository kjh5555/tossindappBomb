## Section 1: Visual Identity Statement

### 핵심 비주얼 룰

> **"빛은 위험이다. 어둠은 안전이다. 읽는 자만이 살아남는다."**

이 한 줄이 모든 시각적 판단의 최종 기준이다. 버튼 색상, 이펙트 강도, UI 밝기 — 어떤 요소가 "이게 맞는 방향인가?" 하는 의문에 부딪힐 때, 이 규칙으로 돌아온다.

### 지원 비주얼 원칙

#### 원칙 1 — 위험 신호는 발광한다 (Danger Emits Light)

폭발 예고, 활성화된 위협 셀, 카운트다운 — 플레이어가 회피해야 할 모든 요소는 네온 발광으로 표현된다. 안전한 셀은 발광하지 않는다. 발광 강도 자체가 위험 수준의 척도다.

*Design test*: "이것은 플레이어가 피해야 하는가?" YES → 발광 추가. NO → 발광 제거.

*연결 필러*: **공정한 죽음** — 발광 없이 죽는 일은 없어야 한다. 위험 신호가 빛으로 명확히 예고되었기 때문에 죽음이 납득된다.

#### 원칙 2 — 그리드는 정보의 언어다 (The Grid Is the Language of Information)

그리드 선은 장식이 아니라 정보 전달 인프라다. 셀 경계, 폭발 패턴, 안전 구역 — 모든 게임 상태는 그리드의 시각적 변화(색상, 두께, 투명도)로 표현되어야 한다. 그리드 외부의 시각 요소는 UI와 피드백 레이어로만 사용한다.

*Design test*: 새 게임 상태/이벤트 표현 시 "그리드 셀 또는 그리드 선의 변화로 표현 가능한가?" YES → 오버레이보다 그리드 변화 우선.

*연결 필러*: **읽으면 이긴다** — 그리드를 읽는 행위 = 게임을 이해하는 행위.

#### 원칙 3 — 화면 밀도는 긴장감이다, 혼란이 아니다

모바일 소형 화면에서 시각 요소는 항상 계층화(hierarchy)되어야 한다.
- **1순위**: 폭발 예고 패턴
- **2순위**: 내 캐릭터 위치
- **3순위**: 상대 플레이어 (반투명)

이 순위를 이탈하는 시각 요소는 존재하지 않는다.

*Design test*: "이것이 폭발 예고 패턴 인지를 0.1초라도 지연시키는가?" YES → 밝기/크기/채도를 낮추거나 제거.

*연결 필러*: **5분의 밀도** + **함께 겨루는 생존** — 상대의 존재는 긴장감의 자산이지, 패턴 읽기의 방해물이 아니다.

### 적용 요약

| 원칙 | 적용 대상 예시 | 금지 케이스 |
|------|--------------|------------|
| 위험 = 발광 | 폭발 예고 셀, 카운트다운 | 안전 셀에 장식용 글로우 |
| 그리드 = 정보 언어 | 패턴 하이라이트, 셀 상태 변화 | 패턴 위에 전체화면 오버레이 |
| 밀도 = 계층화 | 상대방 반투명 처리, UI 최소화 | 플레이어보다 밝은 UI 요소 |

## Section 2: Mood & Atmosphere

### 상태별 무드 타겟

#### Active Round (코어 게임플레이)
- **핵심 감정**: 냉정한 집중 (Cold Focus) — 심박수는 높지만 시선은 차갑다
- **조명**: 차가운 청록-화이트 (5000–6500K), 높은 대비, 심흑색 배경 (10–15% 밝기)
- **서술어**: 서늘한 / 예리한 / 압축된 / 박동하는 / 투명한
- **에너지**: tense
- **핵심 비주얼**: 폭발 예고 셀이 0.5Hz → 4Hz로 가속 박동. 폭발 0.3초 전 박동 정지 → 최대 밝기 고정
- **필러**: 읽으면 이긴다 (박동 주기 읽기 = 이동 타이밍) + 공정한 죽음 (박동이 항상 선행)

#### Round Transition (라운드 전환)
- **핵심 감정**: 숨 고르기 (Controlled Decompression) — 긴장이 해소가 아닌 보류
- **조명**: 중성-약 따뜻 (4000K), 낮은 대비, 전체 밝기 10% 상향
- **서술어**: 평탄화된 / 짧은 / 회복 중인 / 기계적인
- **에너지**: measured
- **핵심 비주얼**: 왼쪽 상단→오른쪽 하단 0.8초 스캔 라인으로 그리드 초기화. 스캔 완료 시 라운드 번호 1초 표시
- **필러**: 5분의 밀도 (전환 1.5초 미만)

#### Last Survivor (마지막 생존자)
- **핵심 감정**: 고립된 통제감 (Isolated Dominance) — 고요하지만 위태로운 정상
- **조명**: 황금-앰버 (2700–3200K) 배경 + 청록 위험 셀 (3중 대비). 내 캐릭터 주변 약한 황금 후광
- **서술어**: 고요한 위험 / 황금빛 고립 / 집중된 / 불안정한
- **에너지**: triumphant (억제 — 차갑게 타오르는)
- **핵심 비주얼**: 그리드 외곽 테두리가 황금빛 1Hz 펄스 시작. 폭발 예고보다 항상 느리고 낮은 채도
- **필러**: 함께 겨루는 생존 (부재가 고립감 강화) + 읽으면 이긴다 (시각적 보상 = 잘 읽었다는 확인)

#### Death / Eliminated (사망)
- **핵심 감정**: 즉각적인 납득 (Instant Comprehension) — 0.5초 안에 이유가 설명됨
- **조명**: 핑크-레드 플래시 (순간 최대 밝기 +50%) → 0.4초 내 급격히 소멸
- **서술어**: 명확한 / 순간적인 / 수용 가능한 / 잔존하는
- **에너지**: suspended
- **핵심 비주얼**: 0.6초 사인 리플레이 — 폭발 셀 핑크-레드 재점등 + 내 위치에 X 마크 (그리드 선 언어). 이후 반투명 형상으로 대기
- **필러**: 공정한 죽음 (사인 리플레이 = 납득의 시각적 구현) + 5분의 밀도 (관전 = 다음 라운드 학습)

#### Lobby / Waiting for Players (대기)
- **핵심 감정**: 차분한 기대 (Calm Anticipation) — 폭풍 전의 고요
- **조명**: 중성-차가운 (4500–5000K), 최저 밝기 (그리드 선 5–8%), 최저 대비
- **서술어**: 잠든 / 미묘한 / 기다리는 / 차가운 공기
- **에너지**: quiet
- **핵심 비주얼**: 접속한 플레이어 수만큼 랜덤 셀이 청록 극저채도로 깜빡임. 전원 접속 시 동시 점등 → 게임 시작
- **필러**: 함께 겨루는 생존 (접속 = 그리드의 빛)

#### Main Menu (메인 메뉴)
- **핵심 감정**: 조용한 초대 (Quiet Invitation) — 설명 없이 보여준다
- **조명**: 차가운 (5500K), 배경 흑색, 로고/CTA만 네온 발광, 그리드 10–12% 밝기
- **서술어**: 간결한 / 자신감 있는 / 준비된
- **에너지**: quiet (정적)
- **핵심 비주얼**: 배경에서 실제 폭탄 패턴이 30% 속도로 자동 루프 — 암묵적 튜토리얼
- **필러**: 읽으면 이긴다 (진입 전부터 패턴 읽기 시작) + 5분의 밀도 (1개 화면 메뉴)

### 네온-온-다크 일관성 규칙

모든 상태에서 배경은 어둡다. **안전 셀이 발광하는 상태는 없다.** 변하는 것은 발광 요소의 색온도, 채도, 주기뿐이다.

| 상태 | 지배 색상 | 밝기 | 대비 | 에너지 |
|---|---|---|---|---|
| Active Round | 청록 + 심흑 | 어둠 + 발광 점 | 최고 | tense |
| Round Transition | 중성 흰-회 | 균일 저밝기 | 낮음 | measured |
| Last Survivor | 황금 앰버 + 청록 | 캐릭터 후광 | 매우 높음 | triumphant |
| Death | 핑크-레드 플래시 | 순간 피크→소멸 | 순간 최고 | suspended |
| Lobby | 청록 극저채도 | 최저 | 최저 | quiet |
| Main Menu | 청록 + 흑 | 중간 | 중간 | quiet |

## Section 3: Shape Language

### 3.1 플레이어 캐릭터 실루엣

**형태 원형: 압축된 기하학 (Compressed Geometry)**

- 외형: 셀 크기 60%의 정사각형, 챔퍼 3px (셀보다 날카롭게 — 그리드에 속하지만 동일하지 않음)
- 방향 지시자: 정사각형 내부 이등변삼각형 (외형의 35%), 꼭짓점이 이동 방향 지시
- 외곽선: 2px solid (그리드 선 1px의 2배 — 계층 차별화)

**내 캐릭터 vs 상대방:**
- 내 캐릭터: 외곽선 흰색 `#FFFFFF` 100% 불투명 + 청록 `#00E5CC` 삼각형. 발광 없음 (Last Survivor 황금 후광 1px 예외)
- 상대방: 동일 형태, 외곽선 40% 불투명도, 내부 삼각형 없음 (빈 윤곽선). 색상 `#606060` — 개별 식별 아닌 군집 존재로 읽힘

*연결*: **공정한 죽음** (방향 지시자로 사망 리플레이 즉시 이해) + **함께 겨루는 생존** (동일 형태로 동류 인식)

### 3.2 그리드 & 셀 지오메트리

**그리드 선:** 1px, 색상 `#2D2D4A` (배경 `#1A1A2E` 대비 15% 밝기). 교차점 장식 없음.

**셀 기본: 챔퍼 2px** (border-radius 아닌 45° 직선 절단)
- 이유: 라운드 코너 = 유기적/안전 감성으로 위험 강도 희석. 완전 직각 = 중립 상태가 불안해 보임. 챔퍼 2px = 기하학 정밀함 유지 + 중립 상태 조용함

**셀 상태별 형태 변화:**

| 상태 | 챔퍼 | 크기 | 발광 |
|---|---|---|---|
| Idle (안전) | 2px | 100% | 없음, 그리드 선만 |
| Warning 1단계 | 2px→1px (0.3초 트윈) | 100% | 인너 글로우 청록 10% |
| Warning 2단계 (가속 박동) | 1px | 102% (미세 팽창) | 인너 글로우 40%, 외곽 발광 1px |
| Imminent (폭발 0.3초 전) | 0px (완전 직각) | 100% 고정 | 최대 밝기 고정, 박동 정지 |
| Exploded | 4px (반팽창) | — | 핑크-레드 플래시 0.1초 → 소멸 |

폭발 직전 챔퍼 0px + 발광 정지 = 압축된 에너지의 역설적 시각 언어.

**패턴 군집 읽기:** 인접 Warning 2단계 셀 사이 그리드 선 두께 0.5px로 감소 → Gestalt 근접성으로 위협 영역이 하나의 덩어리로 인식됨.

*연결*: **읽으면 이긴다** (형태 문법만으로 위험 단계 읽기) + **그리드 = 정보 언어** 원칙

### 3.3 UI 형태 문법

UI는 그리드 언어의 파생물. 독립적 HUD 언어 없음.

- **버튼**: 챔퍼 3px 직사각형, 터치 최소 44×44px. 기본: border 1px `#2D2D4A`, fill 투명. Primary CTA: border 청록, fill 없음, 발광 없음
- **패널**: 챔퍼 4px, 배경 `#0D0D1A` 95%, border 1px `#2D2D4A`. 패널 컨테이너 자체 발광 금지
- **타이머**: 수평 바, 챔퍼 없음, 4px 높이. 위험 임박 시 색상만 청록→핑크-레드 전환 (형태 변화 없음)
- **숫자 카운터**: 모노스페이스 20px, `#FFFFFF` 60% 불투명. 플레이어보다 밝은 UI 금지

**금지 형태:** 원형 버튼/패널, 라운드 코너 8px+, 그라디언트 배경

### 3.4 시각 계층 (Hero vs. Supporting)

| 순위 | 요소 | 무게 원천 |
|---|---|---|
| 1순위 | 폭발 예고 패턴 | 강한 발광 + 챔퍼 감소 군집 |
| 2순위 | 내 캐릭터 | 형태 무게 (2px 외곽선 + 크기) |
| 3순위 | 상대방 | 40% 불투명 윤곽선만 |
| 후퇴 | UI | 4px 타이머 선, 주변시로만 인식 |

예외: 사망 시 X 마크 0.6초간 1순위 계층 점령 → 핑크-레드 최대 발광 → 납득 후 소멸

## Section 4: Color System

### Primary Palette

| 색상 이름 | Hex | HSL | 역할 |
|---|---|---|---|
| **Void Black** | `#1A1A2E` | 240°, 28%, 14% | 안전의 증거 — 발광 없는 것 = 안전 |
| **Grid Slate** | `#2D2D4A` | 240°, 25%, 23% | 정보 인프라 그리드 선 |
| **Danger Cyan** | `#00E5CC` | 174°, 100%, 45% | 위험 신호 — "읽어라" (공황 아닌 분석) |
| **Player White** | `#FFFFFF` | 0°, 0%, 100% | 플레이어 정체성 (발광 없음) |
| **Last Survivor Gold** | `#F5A623` | 37°, 91%, 55% | 마지막 생존자 표식 |
| **Death Rose** | `#FF3366` | 345°, 100%, 60% | 즉각적 납득의 신호 |
| **Opponent Ghost** | `#606060` @ 40% | 0°, 0%, 38% | 맥락적 존재 (개별 식별 대상 아님) |

### Semantic Color Vocabulary

| 의미 | 색상 | Hex | 근거 |
|---|---|---|---|
| 위험/경고 | Danger Cyan | `#00E5CC` | 차가운 빛 = 냉정 분석 (빨강=공황과 구분) |
| 안전/중립 | Void Black (무발광) | `#1A1A2E` | 발광 없음 = 안전의 증거 |
| 플레이어 정체성 | Player White + Danger Cyan | `#FFFFFF` + `#00E5CC` | 흰 외곽선=나의 존재, 시안 삼각형=방향 |
| 상대방 | Opponent Ghost | `#606060` @ 40% | 존재하지만 집중 대상이 아님 |
| 승리/생존 | Last Survivor Gold | `#F5A623` | 차갑게 싸워서 따뜻하게 남은 자 |
| 죽음/탈락 | Death Rose | `#FF3366` | 처벌 아닌 납득의 신호 |
| UI/시스템 | Grid Slate + White @ 60% | `#2D2D4A` / `#FFFFFF`@60% | UI는 게임보다 조용해야 함 |

**핵심 금지 규칙:**
- 안전 셀에 어떤 색상도 발광시키지 않는다
- UI 요소에 Danger Cyan 발광 사용 금지 (flat만 허용)
- UI 요소가 플레이어 캐릭터(`#FFFFFF` 100%)보다 밝을 수 없다

### Color Temperature by Game State

| 상태 | 지배 색 | 색온도 | 허가 색상 | 금지 |
|---|---|---|---|---|
| Active Round | `#00E5CC` | 차가운 5000-6500K | Cyan, White, Ghost | 황금, 핑크-레드, 따뜻한 계열 |
| Last Survivor | `#F5A623` + `#00E5CC` | 따뜻한 2700-3200K | Gold, Cyan 공존 | 무채색 지배 금지 |
| Death | `#FF3366` 순간 피크 | 적외 순간 → 소멸 | Death Rose 0.5초 | 화면 전체 물들이기 금지 |
| Round Transition | 무채색 스캔 | 중성 4000K | 흰 스캔 라인만 | 채도 있는 색상 일체 |
| Lobby | `#00E5CC` @ 5-15% | 잠든 4500-5000K | 극저채도 시안 | 폭발 예고 강도 시안 |
| Main Menu | `#00E5CC` flat + `#FFFFFF` | 5500K | 로고에만 mild glow | 게임 내 발광 강도 초과 금지 |

### Colorblind Safety

**핵심 색상 쌍 평가:**
- `#00E5CC` vs `#1A1A2E`: 색조 아닌 **명도 차이** 기반 → 전체 색각 이상에서 기능
- `#FF3366` vs `#F5A623`: 상호 배타적 상태라 동시 혼동 없음

**3중 백업 시스템:**

| 신호 | 형태 백업 | 애니메이션 백업 | 명도 백업 |
|---|---|---|---|
| 폭발 예고 | 챔퍼 2px→0px 감소 | 0.5Hz→4Hz 가속 박동 | 배경 대비 명도 고차이 |
| 사망 | X 마크 (그리드 선 언어) | 0.1초 플래시 | 순간 최고 밝기 |
| Last Survivor | 외곽 테두리 전체 점등 | 1Hz 펄스 | "LAST SURVIVOR" 텍스트 |

## Section 5: Character Design Direction

### 5.1 비주얼 아키타입 — 압축된 기하학 존재

모든 캐릭터는 **스프라이트 없음, 파티클 없음, 코드-드리븐 렌더링**. Cocos Creator `Graphics` 컴포넌트로 매 프레임 직접 그린다. 이것은 성능 제약이 아닌 비주얼 원칙이다 — 게임의 모든 시각 요소가 그리드와 동일한 기하학 언어로 만들어진다는 선언.

**플레이어 캐릭터 기본 형태:**
- 외형: 셀 크기의 60% 정사각형, 챔퍼 3px (셀 챔퍼 2px보다 날카로움 — 그리드에 속하지만 그리드가 아님)
- 방향 지시자: 내부 이등변삼각형, 외형 크기의 35%, 꼭짓점이 마지막 이동 방향 지시
- 외곽선: 2px solid (그리드 선 1px의 2배)
- 내부 fill: 없음 (투명) — 외곽선과 삼각형만 존재

**캐릭터 간 시각 계층:**

| 구분 | 외곽선 | 삼각형 | 불투명도 | 비고 |
|---|---|---|---|---|
| 내 캐릭터 | `#FFFFFF` 2px | `#00E5CC` fill | 100% | Last Survivor 시 1px gold 후광 추가 |
| 상대 플레이어 | `#606060` 2px | 없음 (빈 윤곽) | 40% | 군집 존재감, 개별 식별 대상 아님 |
| 사망 후 대기 | `#606060` 1px | 없음 | 20% | 관전 상태 — 더 희미하게 |

### 5.2 표현 및 포즈 철학

표현 없음. 포즈 없음. 방향만 있다.

캐릭터는 자율적 감정을 가진 존재가 아닌 **플레이어 의지의 기하학적 표현**이다. 삼각형 방향 = 마지막 이동 벡터. 이것이 이 게임의 "표정"이다.

*금지*: 아이 윤곽선, 원형 캐릭터, 캐릭터 얼굴 요소, 캐릭터 크기 편차 (스킨 포함), 캐릭터 발광 (Last Survivor 황금 1px 후광 제외)

### 5.3 사망 애니메이션 타임라인 (0.6초)

사망은 이 게임에서 가장 중요한 피드백 순간이다. 0.6초 안에 "왜 죽었는지"를 시각으로 설명해야 한다.

| 구간 | 시간 | 시각 | 역할 |
|---|---|---|---|
| **임팩트 플래시** | 0–0.05초 | 캐릭터 위치 `#FF3366` 플래시 3px 원형 확산 → 즉시 소멸 | 죽음 순간 각인 |
| **4-아크 분열** | 0.05–0.25초 | 정사각형 4개 모서리로 챔퍼 조각이 분리, 0.2초 내 페이드아웃 | 내 캐릭터가 파괴됨을 인식 |
| **사인 리플레이** | 0.25–0.55초 | 폭발 셀 `#FF3366` 재점등 (원래 Danger Cyan 강도의 60%) + 내 위치에 `#FF3366` X 마크 1px×1px (셀 크기의 40%) | "왜 죽었는가" 설명 |
| **고스트 전환** | 0.55–0.6초 | X 마크 페이드아웃, 캐릭터 20% 불투명 고스트 형태로 등장 | 관전 모드 진입 |

사인 리플레이 셀 재점등 = 원래 폭발 패턴 재현이며, X 마크는 그리드 선 언어로 그려진다 (대각선 2개, 챔퍼 없음, 발광 없음).

### 5.4 LOD 철학

모든 캐릭터는 단일 디테일 레벨. `Graphics` 컴포넌트 드로우콜 = 캐릭터당 1회 (정사각형 + 삼각형 = 단일 패스). LOD 시스템 불필요.

최대 동시 캐릭터: 6명 (일반 모드 기준). 드로우콜 기여: ≤6 calls.

### 5.5 스킨 시스템 프레임워크

스킨은 **잠긴 레이어 (Locked Layer)** 와 **교체 가능 레이어 (Skinnable Layer)** 로 분리된다.

**잠긴 레이어 — 절대 변경 불가:**
- 외곽선 두께 (2px)
- 챔퍼 픽셀 (3px)
- 캐릭터 크기 (셀 60%)
- 방향 삼각형 크기 (35%)
- 내 캐릭터 외곽선 색상 (`#FFFFFF` — 식별 기준)
- 방향 삼각형 색상 (`#00E5CC` — 위험 언어 일관성)

**교체 가능 레이어:**
- 외곽선 색상 (단, `#FFFFFF`보다 어두운 색상만 허용 — 계층 위반 방지)
- 내부 fill 패턴 (격자, 점선 등 기하학 패턴에 한정 — 이미지 채우기 금지)
- 사망 애니메이션 4-아크 분열 색상 (Danger Cyan 또는 커스텀 단색)

## Section 6: Environment Design Language

### 6.1 그리드 환경 아키텍처

**배경:** `#1A1A2E` flat fill. 비네트 없음. 그라디언트 없음. 배경은 그리드 가독성의 캔버스다 — 그 자체가 시각적 흥미를 가져선 안 된다.

**그리드 프레임:**
- 플레이 영역: 8×8 기본 (GDD에서 확정). 화면 비율에 따른 셀 크기는 `(화면 단변 × 0.85) / 8`로 계산
- 외곽 프레임: 그리드 전체를 감싸는 4px 챔퍼 직사각형 테두리 (색상: 기본 `#2D2D4A`)
- 프레임 여백: 그리드 외곽에서 화면 엣지까지 `(화면 단변 × 0.075)` — UI 영역

**프레임 상태 반응:**

| 게임 상태 | 프레임 색상 | 애니메이션 |
|---|---|---|
| Active Round | `#2D2D4A` (기본) | 없음 |
| Last Survivor | `#F5A623` | 1Hz 펄스, 진폭 30% 밝기 증감 |
| Death | `#FF3366` | 0.3초 점등 → 페이드아웃 |
| Round Transition | `#FFFFFF` @ 20% | 스캔 라인과 동기화 0.8초 |
| Lobby | `#2D2D4A` | 없음 (플레이어 접속 시 셀만 반응) |

Last Survivor 황금 펄스는 폭발 예고 박동보다 항상 **느리고 낮은 채도**로 유지한다. 황금 프레임이 Danger Cyan 셀 발광과 경쟁해선 안 된다.

### 6.2 텍스처 철학

**코드 드리본 = 텍스처 없음.** 모든 그리드, 셀, 캐릭터는 `Graphics` 컴포넌트로 렌더링된다. 이미지 에셋 없음.

*이유*: 텍스처 atlases는 세밀한 상태 전환(챔퍼 2px→0px, 발광 강도 연속 변화)을 프레임 단위로 표현할 수 없다. 코드 드리본 렌더링은 상태를 공식(formula)으로 표현하며, 이것이 "읽으면 이긴다" 원칙과 직결된다.

**예외 에셋 (이미지 허용):**
- 로고 (`assets/art/ui/logo.png`) — vector export 2× 기준
- 토스 SDK 요구 아이콘/배너 (`assets/art/toss/`) — 플랫폼 규격 준수

### 6.3 소품 밀도 규칙

그리드 외부 소품: **없음**. 그리드 내부 소품: **없음**.

배경 장식, 주변 오브젝트, 파티클 환경광 — 일체 없다. 화면 안의 모든 픽셀은 게임 상태 정보이거나 검은 배경이다.

*연결*: **공정한 죽음** — 장식 요소가 0.1초라도 폭발 예고 인지를 방해해선 안 된다.

### 6.4 환경 스토리텔링

그리드 자체가 스토리다. 메인 메뉴에서 실제 폭탄 패턴이 30% 속도로 자동 루프하며, 이것이 이 게임의 "세계관 소개"다.

추가적인 환경 스토리텔링 요소는 없다. 배경 설화, 환경 오브젝트, 월드-빌딩 장식 — 필러 **5분의 밀도**와 배치되므로 채택하지 않는다.

### 6.5 동적 그리드 선 시각화

기본 그리드 선 두께: 1px, `#2D2D4A`.

**Warning 2단계 셀 군집 처리:**
인접한 Warning 2단계 셀들 사이의 그리드 선을 0.5px로 감소시킨다 (0.3초 트윈). Gestalt 근접성 원리 — 위협 구역이 셀 개별 조각이 아닌 하나의 위험 덩어리로 인식된다.

군집 기준: 인접 (상하좌우) 2셀 이상이 Warning 2단계 이상일 때 그 경계선에 적용. 대각선 인접은 미적용.

**그리드 선 두께 상태표:**

| 상황 | 두께 | 전환 |
|---|---|---|
| 기본 | 1px | — |
| Warning 2단계 군집 내부 경계 | 0.5px | 0.3초 ease-in |
| Imminent 셀 경계 (폭발 0.3초 전) | 1.5px | 0.1초 즉시 |
| Round Transition 스캔 중 | 0px → 1px | 스캔 라인 통과 후 재생성 |

## Section 7: UI/HUD Visual Direction

### 7.1 Diegetic vs. Screen-Space HUD 철학

**결론: 반-다이제틱 (Semi-Diegetic)**

HUD는 그리드 시각 언어에서 파생된 형태를 사용하되, 그리드 내부에 배치되지 않는다. 모든 HUD 요소는 그리드 외곽 여백 (`화면 단변 × 0.075` 영역)에만 존재한다.

- HUD 요소의 형태 문법 (챔퍼, 선 두께, 색상) = Section 3.3 UI 형태 문법과 동일
- HUD는 게임 상태를 수동적으로 표시한다 — 플레이어의 주의를 능동적으로 요구하지 않는다
- **HUD 발광 금지: 예외 없음**

### 7.2 Typography Direction

**폰트 특성:**
- **분류**: Monospace (등폭) 계열
- **자형**: Condensed-to-Regular 너비. 수직 비율 높음 (cap height ≥ 70% em-square)
- **웨이트**: Regular (400) + Bold (700) 두 가지만. 이탤릭 금지
- **숫자**: Tabular numerals 필수 — 숫자 변경 시 레이아웃 흔들림 없음
- **문자 구분**: 1/l, 0/O 명확히 구분되는 폰트 필수
- **대소문자**: ALL CAPS 전용. 소문자 금지

*이유:* Monospace = 코드/데이터/시스템 연상. 라운드 번호 "ROUND 07"이 게임 UI 위젯이 아닌 시스템 출력처럼 읽혀야 한다.

**크기 계층:**

| 레벨 | 역할 | 크기 | 웨이트 | 색상 | 용도 |
|---|---|---|---|---|---|
| **Level 1 — Primary** | 즉각 인지 정보 | 28px | Bold 700 | `#FFFFFF` @ 100% | 라운드 번호, 생존자 수 |
| **Level 2 — Secondary** | 보조 상태 정보 | 18px | Regular 400 | `#FFFFFF` @ 60% | 순위, 탈락 인원 |
| **Level 3 — Label** | 범주 레이블 | 12px | Regular 400 | `#FFFFFF` @ 40% | "ROUND", "ALIVE", "PLAYERS" |

Level 1 수치는 Level 3 레이블과 항상 쌍으로 등장 (레이블 위, 수치 아래, 간격 4px).

### 7.3 Iconography Style

**아이콘 없음.** 텍스트 레이블과 기하학 마커만 사용한다.

*이유:* `Graphics` 컴포넌트 환경에서 이미지 아이콘은 별도 에셋 로딩 = Section 6.2 위반. 아이콘은 해석 단계를 추가하며, 이 게임에서 그 0.1초는 비용이다.

**허용 기하학 마커:**

| 용도 | 형태 | 색상 |
|---|---|---|
| 사망 표시 | X 마크 (대각선 2개, 1px 선, 챔퍼 없음) | `#FF3366` |
| 마지막 생존자 | 외곽 프레임 황금 펄스 + "LAST SURVIVOR" 텍스트 | `#F5A623` |
| 방향 지시 | 내부 삼각형 (캐릭터 내) | `#00E5CC` |
| 구분선 | 수평 1px | `#2D2D4A` |

### 7.4 HUD Element Layout

```
┌─────────────────────────────────────────┐
│  [ROUND 07]           [ALIVE 03/06]     │  ← 상단 여백
│                                         │
│  ┌─────────────────────────────────┐   │
│  │          8×8 GRID               │   │
│  └─────────────────────────────────┘   │
│  [══════════════════════░░░░░░░░░░░]   │  ← 타이머 바 (6px)
└─────────────────────────────────────────┘
```

| HUD 요소 | 위치 | 정렬 | 이유 |
|---|---|---|---|
| 라운드 카운터 ("ROUND 07") | 상단 좌측 | left, 그리드 좌측 엣지 정렬 | 읽기 방향 시작점, 맥락 정보 |
| 생존자 카운터 ("ALIVE 03/06") | 상단 우측 | right, 그리드 우측 엣지 정렬 | 시선이 패턴 읽기 후 자연스럽게 이동 |
| 타이머 바 | 하단 전체 폭 | full-width | 주변시 인지용, 중앙 시야 방해 금지 |

**터치 존 회피:** 화면 하단 20% 영역에 터치 대상 HUD 요소 배치 금지. 타이머 바는 표시 전용(non-interactive)이므로 하단 허용.

**상단 HUD 간격:**
- Safe area 하단 엣지에서 8px 아래
- Level 3 레이블 (12px) 상단 기준
- Level 1 수치 (28px)는 레이블 아래 4px

#### 타이머 바 상세 스펙

- 높이: **6px** (주변시 인지 최적화)
- 위치: 그리드 하단 외곽 프레임에서 8px 아래
- 너비: 그리드 너비와 동일
- 챔퍼: 없음 (직각) — 진행 중인 소모를 표현
- 기본 색상: `#00E5CC` @ 60%
- 경고 임박 (잔여 20% 이하): `#FF3366` @ 80% (500ms 선형 전환) + **0.5Hz 깜박임** (color-only 의존 방지 — 색맹 안전)
  - `prefers-reduced-motion` 설정 시 깜박임 생략, 색상 전환만 적용
- 감소 방향: 왼쪽→오른쪽 감소 (읽기 방향 일치)
- 배경 트랙: `#2D2D4A` 1px (6px 바 아래 1px 선)

### 7.5 UI Animation Feel

**모션 언어: 기계적-즉각 (Mechanical-Immediate)**

스프링 없음. 오버슈트 없음. 바운스 없음. 모든 전환은 기계 장치처럼 작동한다.

| UI 이벤트 | 지속 시간 | 이징 | 세부 |
|---|---|---|---|
| 버튼 탭 피드백 | 80ms | ease-out | border 색상 → `#FFFFFF` @ 60% → 원복. 크기 변화 없음 |
| 화면 전환 | 200ms | linear | `#1A1A2E` fade-in 100ms → 새 씬 fade-in 100ms |
| 라운드 번호 변경 | 120ms | ease-in | 현재 opacity 100%→0% (60ms) + 새 수치 0%→100% (60ms). 위치 이동 없음 |
| 생존자 카운터 감소 | 80ms | linear | `#FFFFFF`→`#FF3366`→`#FFFFFF` 즉시 교체 |
| 타이머 경고 전환 | 500ms | linear | Cyan @ 60% → Rose @ 80% |
| 라운드 시작 번호 | 100ms fade-in + 800ms 체류 + 100ms fade-out | — | 화면 중앙, 28px Bold, `#FFFFFF` |
| "LAST SURVIVOR" | 100ms fade-in + 1000ms 체류 + 100ms fade-out | — | `#F5A623`, 체류 중 1Hz ±10% opacity 미세 진동 |

**금지 모션:** Transform scale, 슬라이드-인 (모든 방향), 블러 전환, 파티클 UI 피드백, 300ms 초과 UI 애니메이션 (체류 텍스트 제외)

**버튼 상태 (3가지):**

| 상태 | 외곽선 | fill | 텍스트 |
|---|---|---|---|
| Default | `#2D2D4A` | 없음 | 60% |
| Pressed (80ms) | `#FFFFFF` @ 60% | 없음 | 100% |
| Disabled | `#2D2D4A` @ 30% | 없음 | 30% |

Primary CTA: Default border `#00E5CC` flat / Pressed `#FFFFFF` @ 80% / Disabled `#00E5CC` @ 30%

### 7.6 In-Game Overlay Rules

**그리드를 가리는 전체화면 오버레이는 없다.** 죽은 플레이어도 그리드를 봐야 한다 — 관전 중 다음 라운드 패턴 학습이 "5분의 밀도" 필러를 지지한다.

#### 사망 오버레이

0.6초 사망 애니메이션 (Section 5.3) 이후:
- 그리드 반투명 레이어 없음 — 그리드 완전히 보임
- 내 캐릭터: 20% 불투명 고스트 전환 (solid 외곽선, fill 없음)
- 하단 타이머 바 영역: "ELIMINATED" Level 2 텍스트, `#FF3366`, 2초 체류 후 fade-out
- 생존자 카운터: 80ms 색상 플래시로 즉시 업데이트

#### 라운드 종료 오버레이

- 그리드 위 `#1A1A2E` @ 60% dim 레이어 (그리드 선 보임, 활성 발광 소멸)
- 중앙 오버레이 텍스트: "ROUND [N] CLEAR" 28px + 탈락 순서 18px (최대 2줄)
- **총 체류 시간: 1.0초** → fade-out 200ms → clean frame 200ms → 라운드 전환 스캔 시작
- **전체 라운드 전환 시간: ≤1.4초** (필러: 5분의 밀도 준수)

clean frame 200ms = 스캔 라인 시작 전 그리드가 완전히 초기화된 상태가 보이는 구간. 이전 라운드 발광 잔상 없음 보장.

#### 마지막 생존자 발표

- 그리드 오버레이 없음, 게임 계속 진행
- 외곽 프레임: `#F5A623` 1Hz 펄스 시작 (Section 6.1)
- 상단 HUD: "LAST SURVIVOR" 28px `#F5A623` (라운드 카운터 위치 일시 점유)
- 게임 종료까지 유지

#### 게임 오버 결과 화면 (유일한 전체화면 예외)

- 200ms linear fade-in, `#1A1A2E` 배경
- 챔퍼 4px 패널 (화면 80% 너비), 내용:
  1. "GAME OVER" / "YOU WIN" — 28px `#FFFFFF` @ 100%
  2. 구분선 1px `#2D2D4A`
  3. 생존 라운드 수 — 28px + "ROUNDS SURVIVED" 12px 레이블
  4. 순위 (해당 시) — 18px `#FFFFFF` @ 60%
- Primary CTA "PLAY AGAIN"
- 배경: 실제 폭탄 패턴 30% 속도 루프 (메인 메뉴와 동일)

## Section 8: Asset Standards

> **포맷 결정 노트:** Art-director는 PNG 단일화를, Technical-artist는 WebP 사용을 제안했다. 에셋 카테고리가 로고·아이콘 2종뿐이므로 압축 이득보다 webview 알파 채널 안정성이 중요하다. **PNG 단일화로 결정.**

### 8.1 이미지 에셋 스펙

GRID REAPER의 이미지 에셋은 두 카테고리뿐이다: **게임 로고**와 **토스 플랫폼 요구 에셋**. 모든 게임플레이 렌더링은 `Graphics` 컴포넌트이므로 이미지 에셋은 사실상 최소화된다.

#### 파일 포맷

**PNG — 유일한 허용 포맷.**

| 포맷 | 판단 | 이유 |
|---|---|---|
| **PNG** | **채택** | Cocos Creator 3.8.6 webview 알파 채널 완전 보장. 무손실. 토스 SDK 공식 지원. |
| WebP | 불채택 | Android 구형 기기 webview에서 알파 채널 렌더링 불안정. 에셋 수 극소수라 압축 이점 불필요. |
| SVG | 불채택 | Cocos Creator 에셋 파이프라인이 런타임 SVG를 직접 지원하지 않음. 사전 변환 단계 없이 PNG로 직접 출력. |

**내보내기 설정:**
```
Color Profile : sRGB IEC61966-2.1
Bit Depth     : 32-bit (RGB + Alpha)
Interlace     : None
Metadata      : Strip all
Premultiplied : false (Cocos Creator 처리와 충돌)
```

#### 해상도 스탠더드

**기준: 2× export.** 3× 기기 대응은 렌더링 레이어(`cc.resolutionScale`)에서 처리.

| 에셋 | 논리 크기 | 내보내기 크기 | 최대 파일 크기 |
|---|---|---|---|
| 게임 로고 (가로형) | 240×80px | 480×160px | ≤30KB |
| 토스 앱 아이콘 | 512×512px | 512×512px | ≤80KB (플랫폼 고정 규격) |
| 토스 스플래시 배너 | 360×200px | 720×400px | ≤50KB |

**로고 비율 잠금:** 코드에서 가로세로 비율을 고정. 어떤 화면에서도 stretch 없음.

**텍스처 하드 리밋 (Technical-artist 규정):**
- 단변 최대: **2048px** (4096px 초과 금지 — webview 크래시 위험)
- POT(2의 거듭제곱) 치수 강제 준수
- GPU 압축 포맷(ASTC, ETC2, S3TC) **사용 금지** — webview WebGL 익스텐션 미보장

### 8.2 폰트 에셋 스탠더드

#### 포맷

**TTF — 유일한 채택 포맷.** Cocos Creator 3.8.6 에셋 파이프라인 네이티브 지원. WOFF2는 CSS 웹 환경 전용 포맷이며 Cocos Creator 직접 임포트 불가.

#### 서브셋 요구사항

GRID REAPER는 ALL CAPS + 숫자만 사용한다. 전체 유니코드 폰트 파일 그대로 사용 금지.

**필수 서브셋 (~40글리프):**
```
대문자 A–Z  : 26글리프
숫자 0–9    : 10글리프
특수문자    : / . - : (HUD 표기용)  +  공백
```

```bash
# 서브셋 생성 (pyftsubset / fonttools)
pyftsubset MonospaceFont.ttf \
  --unicodes="U+0020,U+002D,U+002E,U+002F,U+003A,U+0030-0039,U+0041-005A" \
  --output-file="MonospaceFont_subset.ttf" \
  --no-hinting \
  --desubroutinize
# 목표 파일 크기: ≤30KB (풀 TTF 대비 ~95% 절감)
```

**폰트 아틀라스 규격:**
- 크기: **512×512px RGBA8** (~1MB)
- 3개 크기(28px / 18px / 12px) 단일 아틀라스에 패킹
- Cocos Creator `Label` 컴포넌트 `cacheMode`: 정적 텍스트는 `BITMAP`, 동적 업데이트 빈번한 HUD 숫자는 `CHAR` — 실기기 draw call 비교 후 결정
- 문자 집합은 서브셋만 지정. 전체 Unicode 로딩 금지.

#### 폴백 정책

**폴백 없음.** 폰트 파일은 빌드 번들에 포함(`assets/fonts/`). CDN/외부 URL 로딩 금지. 런타임에서 시스템 폰트로 대체되면 즉시 버그 리포트.

### 8.7 Critical Guardrails

**G1 — Graphics 노드 개별 생성 금지 (draw call 예산 사수)**
64개 셀을 64개 `Graphics` 노드로 구현하면 한도 50을 즉시 초과한다. 동일 레이어는 반드시 단일 `Graphics` 컴포넌트에 통합.

**G2 — 텍스처 2048px 초과 금지 (webview crash 방지)**
Import Settings에서 `Max Size: 2048` 강제 설정. 이 값을 높이려면 명시적 승인 필요.

**G3 — GPU 압축 텍스처 사용 금지 (webview 익스텐션 미보장)**
ASTC, ETC2, S3TC 비활성화. PNG만 허용. 예외는 실기기 익스텐션 검증 완료 후 Lead Programmer 승인 시에만.

**G4 — 게임플레이 중 오브젝트 동적 생성 금지 (GC 스파이크 방지)**
폭발 이펙트, 메시지 파싱 버퍼 등 모든 런타임 오브젝트는 오브젝트 풀에서 재사용. 힙 톱니파형 발생 시 즉시 조사.

**G5 — 단일 씬 메모리 100MB 초과 금지 (150MB 한도 사수)**
씬 전환 시 이전 씬 에셋 명시적 언로드 (`assetManager.releaseAsset`). 스프린트마다 실기기 메모리 스냅샷 1회 의무화.

### REF-01 | *Tron: Legacy* (2010, 영화)
**담당 영역: 색상 & 대기**

**가져오는 것:**
차가운 청록-화이트 발광이 완전한 흑색 위에서 작동하는 방식 — **발광이 물체를 밝히지 않고, 발광 자체가 물체다**라는 원칙. 그리드 선의 빛이 환경 조명을 만들지 않고 그 선 자체로 존재하는 방식. 색온도 5000–6500K의 차가운 청록이 공황이 아닌 분석적 냉정을 유발하는 방식.

**가져오지 않는 것:**
서사적 맥락, 세계관 장식, 그라디언트 헤일로 (주변을 물드는 환경 발광). GRID REAPER의 발광은 '위험 신호'이지 '분위기 조명'이 아니다. 트론의 발광이 아름다움을 위해 존재한다면, 이 게임의 발광은 정보 전달을 위해 존재한다.

**연결:** 공정한 죽음 + 원칙 1 (위험 신호는 발광한다)

### REF-02 | *Superhot* (2016, 게임)
**담당 영역: 위험 커뮤니케이션 시스템**

**가져오는 것:**
단색 또는 극도로 제한된 팔레트 안에서 위협 오브젝트를 배경으로부터 즉각 분리하는 방식. **"팔레트를 줄일수록 각 색의 의미 가중치가 높아진다"**는 설계 원칙. Danger Cyan이 Void Black 위에서 즉각 읽히는 이유는 이 원칙이 작동하기 때문이다.

**가져오지 않는 것:**
3D 공간감, 시간 정지 메카닉 연계 시각 언어. GRID REAPER는 살아있는 그리드 위에서 항상 동시다발적으로 읽힌다 — Superhot처럼 세계가 멈추는 전환이 아니다.

**연결:** 읽으면 이긴다 + 원칙 2 (그리드는 정보의 언어다)

### REF-03 | *Nuclear Throne* (2015, 게임)
**담당 영역: 캐릭터 & 모션 언어**

**가져오는 것:**
캐릭터가 표정 없이 **방향과 위치만으로 의도를 전달하는 방식.** 위에서 내려다보는 시점, 작은 캐릭터 크기, 커다란 위협 속에서도 '내 캐릭터'를 즉시 식별하게 만드는 **외곽선 우선 접근법** — 실루엣이 상태를 말한다.

**가져오지 않는 것:**
유기적 캐릭터 디자인, 표정/스프라이트 애니메이션, 무기/파티클 이펙트. GRID REAPER의 캐릭터는 외곽선과 삼각형만이며 서사가 없다 — 순수한 위치 정보의 기하학적 표현이다.

**연결:** 공정한 죽음 + 함께 겨루는 생존

### REF-04 | *Keep Talking and Nobody Explodes* UI (2015, 게임)
**담당 영역: UI/정보 디자인**

**가져오는 것:**
아이콘 없이 텍스트 레이블 + 기하학 마커만으로 UI를 구성하는 방식. 모노스페이스 올캡스 텍스트가 레이블이 아닌 **시스템 출력**으로 읽히는 타이포그래피 감각. 계기판처럼 단조롭지만 계층화된 정보 구조.

**가져오지 않는 것:**
긴 설명 텍스트, 튜토리얼 팝업, 멀티스텝 UI 계층. KTaNE는 정보를 읽고 처리하는 게임이지만, GRID REAPER의 HUD는 읽는 데 0.1초도 써서는 안 된다. "정보 밀도"가 아닌 **"정보 즉각성"** 이 기준이다.

**연결:** 5분의 밀도 + 원칙 3 (화면 밀도는 긴장감이다)

---

### REF-05 | *Hades* 사망 피드백 (2020, 게임)
**담당 영역: 사망 애니메이션 & 피드백 리듬**

**가져오는 것:**
사망이 처벌이 아닌 즉각적 이해의 순간이 되도록 설계하는 방식. 구체적으로 **충격(플래시) → 원인 제시(리플레이) → 상태 전환(관전)** 이라는 박자 구조. 0.6초 사망 타임라인의 리듬 원형.

**가져오지 않는 것:**
서사적 독백, 사망 후 화면 전환 연출, 캐릭터 정체성 기반 리액션. GRID REAPER의 사망은 스토리 없는 순수 피드백이다. 사인 리플레이는 "이유 설명"이지 "드라마틱한 장면"이 아니다.

**연결:** 공정한 죽음 + 5분의 밀도
